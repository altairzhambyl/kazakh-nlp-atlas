## Findings

> [!note] CLAIM — mteb-upstream-contrib-process
> Commit message convention (not strictly enforced but recommended): prefix `dataset:` for new datasets/benchmarks to trigger semantic-release version bump; `fix:` patch, `feat:` minor, `breaking:` major, `model:` for new models; `docs:`/`chore:`/`refactor:` do not bump version and following this isn't required if you don't intend to trigger a release.
> **Source:** https://raw.githubusercontent.com/embeddings-benchmark/mteb/main/docs/CONTRIBUTING.md · **Sweep:** `2026-07-mteb-upstream-recon`

> [!note] CLAIM — mteb-upstream-pr-precedents
> mteb's semver/commit-message convention treats new dataset PRs as version-bump-triggering: a commit/PR title prefixed 'dataset:' (matching all 5 PR titles examined: 4710, 4487, 4521, 3991, 4226, 3876) auto-triggers a package version bump and PyPI/GitHub release on merge to main, so a Kazakh-retrieval PR should follow the same 'dataset: ...' title convention.
> **Source:** https://raw.githubusercontent.com/embeddings-benchmark/mteb/main/docs/CONTRIBUTING.md · **Sweep:** `2026-07-mteb-upstream-recon`
